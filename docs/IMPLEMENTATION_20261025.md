# OSZ 插件迁移与验证（2026-10-25）

## 1. 边界

归档接口的输入对象是 `.osz` 压缩包。插件首先调用通用归档枚举，再读取其中的 `.osu` 元数据，返回独立音频成员及对应背景。视觉扩展接受 `.osu` 时间线文本，但没有独立 `.osu` 歌曲导入能力。

| 位置 | 职责 |
| --- | --- |
| `src/plugin.cpp` | OSZ 路径入口、ABI 协商、包内枚举、读取限制、回调错误和背景字节返回 |
| `src/parser.cpp` | 包内元数据解释、引用路径校验、音频收集与去重、逐音频背景关联 |
| 播放器 `osu_plugin_client.cpp` | 定位并加载 DLL，提供通用归档 I/O 回调，将 ABI 结果转成宿主对象 |
| 播放器导入器／播放源／文件属性 | 使用插件结果添加歌曲；已有解码器播放；内嵌封面优先；压缩包只读 |

播放器保留 `.osz` 后缀识别、打开筛选器、归档成员身份和后缀保护。这些用于格式分派，不保留谱面解析副本。缺少或不兼容的 DLL 会使 OSZ 导入报错，普通 ZIP／RAR 继续使用原有流程。

## 2. 解析规则

1. OSZ 内按归档顺序处理谱面；读取 `[General]` 中的 `AudioFilename`。
2. 接受 UTF-8／BOM、CRLF／LF、数字版本头和带引号的文件名；拒绝无效 UTF-8、NUL 和缺失头信息。
3. 引用相对于所在谱面目录，统一分隔符和 `.`／合法 `..`，匹配不区分大小写，保留归档实际成员名。
4. 禁止越过包根、绝对路径、盘符和 URL。不存在的引用不作为歌曲，不猜测包内任意音频。
5. 不同难度的同一音频只保留一次。多音频全部返回，保持首次引用顺序。
6. 背景只取引用同一音频的谱面首次有效背景；不借用其它歌曲背景。不解析视频和击打音效作为音乐。
7. 封面顺序：音频内嵌封面 → 插件返回的对应背景 → 无封面。

限制：每次最多 256 份谱面、64 MiB 谱面文本；单个元数据或图片成员最多 16 MiB；目录最多 1,048,576 个成员、累计 32 Mi UTF-16 码元、每个名称不超过 32,767 码元。超限或读取失败不返回成功的部分列表。

## 3. ABI 与生命周期

`ttp_osu_query(1, ...)` 返回 `resolve`／`cover`。两者都接受 OSZ 路径，通过宿主提供的 `list_members`／`read_member` 访问压缩包。

- 输出字符串和图片仅在回调期间有效，宿主复制结果。
- 成员读取缓冲区由宿主管理，在下次读取或整个调用结束前有效，插件不释放。
- 调用同步执行，进度和取消继续在调用线程传递；DLL 不启动常驻线程。
- 插件内部异常转为 HRESULT；宿主回调捕获自身异常。CRC、短读、取消和内存不足保留错误码。
- 导入先完整扫描，再交付结果；任一回调失败，宿主丢弃本次结果。
- 播放器只加载 EXE 同目录 `AddIn/ttp_osu.dll`，成功后持有模块，不使用工作目录／PATH 寻找同名文件。

## 4. 构建与兼容

独立 CMake 项目，x86、C++20、VC-LTL／YY-Thunks、体积优化。无新增音频解码库；归档使用系统基础入口，视觉扩展使用 XP 已有的 User32／GDI32／GDI+／OLE32，D3D9 按需从系统目录加载。构建时静态检查 XP 和 Win7 导入清单，运行时由宿主协商 ABI。

原版播放器不支持此新增归档 ABI；本项目没有声称恢复原版中不存在的 OSZ 支持。后续如果要支持原版播放器，需要另行设计宿主接入。

## 6. 节拍视觉扩展

### 6.1 职责与入口

视觉实现位于 DLL，宿主没有 FFT、节拍、粒子或绘制算法的另一份副本。旧 `ttp_osu_query`／OSZ ABI 1 不变；新增序号 2 `ttp_osu_query_visual`／视觉 ABI 1。

| 文件 | 职责 |
| --- | --- |
| `include/ttp_osu/visual.h` | 版本协商、实例、设置、PCM/播放时钟、图片、窗口呈现、统计接口 |
| `src/visual_api.cpp` | 异常转 HRESULT、实例同步、归档时间线选择与取消隔离 |
| `src/visual_scene.cpp` | FFT2048、谱面红/绿线、拍号、Kiai、徽标、频谱、粒子、闪光与视差 |
| `src/visual_renderer.cpp` | 有序四边形、预乘 alpha/加色、CPU 栅格、D3D9 批次与设备生命周期 |
| `assets/TTPlayer.png` | 用户提供的中心图案，原样嵌入 RCDATA 101 |
| 播放器 `osu_visual_client.cpp` | 音频/时钟快照、通用归档读取、后台封面解码、窗口与输入桥接 |

所有借用输入在调用返回前处理/复制，DLL 不保留宿主回调。归档 I/O 在锁外执行，读取结束后以 generation 校验提交。D3D9 创建、呈现、Reset、detach 和最终销毁在 HWND 所属线程完成。宿主重设父窗口或销毁 HWND 前先 detach。

播放器增加类型 7「节拍星环」，同时接入主窗口菜单、视觉菜单、全屏配置、皮肤配置和选项页。五个开关控制频谱、星星、闪光、视差、徽标；可设置备用 BPM（20–400）、基础色、背景色。视觉 FPS 选项扩大至 10–100，旧设置仍可读取。

### 6.2 音频和时间线

原 512 帧视觉接口保持不变，新增连续 2048 帧接口。输出位置、FFT 窗口起点与 timeline revision 分开保存。DirectSound 从真实播放游标读取环形缓冲；waveOut、WASAPI、KS、ASIO 按实际输出队列连接连续片段，遇到缺口停止，不拼接不同 UI 帧。

当四个低延迟输出包总共不足 2048 帧时，使用从已提交 PCM 维护的 4096 帧有界历史；不加输出延迟、不让解码器重复读取。节拍使用真实 `playback_frame`，FFT 使用完整窗口，左右峰值使用 `pcm_cursor_offset` 指示的游标：优先前向 20ms，不足时使用末端已有的最近 20ms。打开初期历史不足、seek 未完成或时间线不匹配时不提交错误 PCM。

FFT 使用 Hann 窗和 1.6 倍幅度标定。固定半幅、bin 64 正弦与本机 BASS 对照：BASS `0.499964535`，DLL `0.799943209`，BASS × 1.6 为 `0.799943268`。此项证明该输入的 FFT 幅度标定，不代表所有 DSP/音量链路与 osu! 逐样本等价。

谱面解析支持红线拍长/offset/meter、绿线继承和 Kiai 位。多难度沿用归档枚举首匹配策略，不自行选择最高难度。当前曲目切换和异步封面刷新都会发布新的 Source；旧读取结果不能覆盖新曲。背景与时间线属于同一次请求，视觉辅助读取不额外弹出密码/分卷窗口。

### 6.3 场景与图像

环形频谱为 1024 个条纹、四次角度重叠，保留 10ms 推进和按时间衰减。Kiai 入口发射左右各 100 颗星，每对间隔 10ms，按时间推进重力、旋转与透明度；粒子最多 600、扩散环最多 8。seek 到 Kiai 段中不会补喷旧入口，长停顿不无限追赶。

层序为背景 → 闪光/扩散环/星星 → 环形频谱 → 中心图案/光环。背景按比例铺满并留视差余量。CPU 和 GPU 共用有序场景，普通混合使用 ONE/INVSRCALPHA，加色使用 ONE/ONE，避免重复乘透明度。

中心 PNG 为用户文件 `TTPlayer.png` 的完整原始字节，488×488、159,963 字节，SHA256 `8dad422e586e99990de755aad60484fc23f143a99020edbd22eee7dc5470a3ee`。系统 GDI+ 1.0 仅在首次加载资源时解码为 PBGRA；不依赖外部图片、BASS、OpenTK 或 osu! 安装。

主窗小区域、皮肤合成与 HDC 回调使用 CPU；独立全屏优先 D3D9，设备不可用时可用 CPU。CPU 复用 DIB，旋转细频谱采用逐扫描线裁剪；GPU 缓存纹理并保持层序合批。provider 合成不调用 swap chain，避免覆盖皮肤或歌词。能取得实际内容区域时按该区域映射鼠标；旧 provider 仅提供无所属窗口的内存 DC 时将指针保持居中，避免把隐藏窗口坐标误当成可见画面。

## 7. 可选插件的入口管理

- 根据实际 DLL 的接口协商结果分别判断 OSZ 与视觉能力，不仅检查文件是否存在。结果在进程内缓存；安装、移除或更新后重启。
- 缺少 OSZ 能力时移除打开文件的 `*.osz` 筛选项，目录扫描与媒体库监视跳过 OSZ。文件格式识别仍保护 `.osz`，不退回普通 ZIP 导入全部音效，不提示改名 ZIP。显式拖入 OSZ 时说明需要可选插件。
- 缺少视觉能力时隐藏主窗/视觉/歌词/全屏菜单中的节拍星环、视觉类型下拉项、整组标签页和全屏 profile 项；点击循环跳过类型 7。
- 已保存的主视觉、歌词内容及全屏类型 7 改用类型 2 频谱分析，颜色/BPM 等插件设置保留。皮肤传入旧类型 7 同样不会产生空白占位或更新提示。
- 只有旧 OSZ 接口的 DLL 保留归档入口；不因缺少新视觉接口禁用旧归档能力。
- 主程序打包不读取 `osu-component.json` 或 `ttp_osu.dll`，即使本机安装了插件也不将其混入主程序包。发布时由 ExtraAddIn 下载并审核可选插件。

本轮在 Windows 11 使用四个隔离目录运行实际播放器 UI 测试：无插件、新版实际 DLL、仅有旧归档接口的测试 DLL、不兼容 DLL，均通过能力判断、文件筛选、菜单、效果循环、旧设置归一化、标签页/控件及全屏下拉项检查。原有 OSZ 回归 315 项以及缺失/不兼容各 7 项通过。

分别在有插件和完全没有插件及其 sidecar 的目录中打包，两个主程序 ZIP 均通过内容和 SHA256 校验且不包含 OSU。ExtraAddIn 的本地组包路径通过实际独立发行 ZIP 的 SHA/CRC、两个导出、文件版本及 XP/Win7 导入校验，并拒绝只有归档导出的旧 DLL。更新后的主程序已重新构建并通过 XP/Win7 静态导入审计；本轮可选入口的完整 UI 流程未另行在虚拟机运行。未下载全部在线插件或发布 Release。

## 8. 布局复核、仅全屏与图案切换（2026-10-25 后续）

本节记录最终实现，替代第 6 节中“主窗口可显示”、旧 PNG 尺寸和旧产物哈希。二进制身份、方法 token 和证据范围详见播放器文档 `docs/OSU_MAIN_MENU_VISUAL_ANALYSIS_20261025.md` 第 14 节；并未将静态证据描述为原 osu! 运行时逐像素对照。

### 8.1 原版布局恢复

- 位置采用 H/480、纹理采用 H/768；1080px @2x 中心资源等效为 540px，再换算成 337.5 逻辑宽度。不能将位置与纹理都按 H/480 放大。
- 频谱尺寸为 `71.875 × bar`、厚度 11.875，扩散环名义直径 325；频谱根半径和原圆形命中半径独立保留。
- 侧闪尺寸 193.75×480，固定两侧并镜像，不跟随前景视差。星星按 33:34 保持比例并随前景；一轮喷射共享扇形方向，每对共享寿命/缩放/旋转，左右速度独立取样。
- 背景使用原中心空闲状态的完整亮度；背景 /180、前景 /60 的视差分别计算。层序为背景、侧闪、扩散环、星星、频谱、图案、光环。
- 圆形鼠标命中采用当前脉冲/悬停缩放及实际偏移后的中心。有效画布高度取 `min(H, floor(W*0.8))`；窄屏采用原可选分支中的居中留黑，鼠标同步换算。
- 普通模式、歌词窗口及皮肤 provider 不显示类型 7；视觉全屏和组合全屏可显示。退出全屏恢复进入前的普通视觉设置，保存配置不会把全屏类型 7 写回普通视觉。

### 8.2 源图与可选 ABI 2

## 13. TTPlayer专用RG进场纹理（2026-10-25）

本节更新第11节的纯PNG入场分支。正常显示仍直接使用原彩色 `TTPlayer.png`；仅开启星环lazer进场并选择千千静听徽标时，使用新生成的专用进度纹理。

### 时间轴与数据

- 采用原 `IntroTriangles` 的2080～3000ms揭示段，920ms线性进度、960逻辑尺寸，以及原内外容器的缩放曲线。先画白色highlight，再画Gray(.6)的background；3000ms后移除描绘层，显示彩色PNG和原有白闪。
- `ttplayer-lazer-intro-highlight.png`、`ttplayer-lazer-intro-background.png` 均为1080×1080 RGB数据，嵌入资源113/114。R为阈值、G为透明度、B为0、文件自身alpha为255，采用严格 `R < progress` 规则。
- 专用纹理只包含TTPlayer图案的外环、内环、耳机和波形；采用原版RG纹理的进度分布匹配描绘节奏。这是对用户图案的适配，不是原程序包含的TTPlayer资源，也不宣称与原程序D3D11输出逐像素相同。
- `TTPlayer.png` 的SHA256保持 `ebe8e9d93bdc59ed28a429f4bf970622376d4dd81e16ea54fe9094a9f9163d28`。完成后保留原橙色外环，不加常驻白圈；自定义图片继续采用原有缩放/透明度入场。
- 不修改ABI5、宿主设置或进场默认关闭的行为；只需更新可选DLL。

### 根据平滑度反馈修正

初次按颜色阈值提取的轮廓将耳机金属反光误识别为小圈和台阶。已改为按原PNG结构标定的三次贝塞尔曲线与解析圆，保留耳机主体、圆弧及波形的几何拐角；不描绘反光边缘。覆盖率使用4倍超采样和抗锯齿降采样，外圆描边向内收2.5像素，使线宽留在原图alpha范围之内。

还修复了短线段生成R通道时的接缝空洞：各段以圆端覆盖完整抗锯齿区域，所有G非零像素都必须有有效R阈值。这样实际动画不会因R=255残留而出现永久黑点。生成器有相应校验，测试另检查耳机两侧每行只有内外两条平滑边界。

## 14. 本地歌曲库（2026-10-26）

本节扩展前述 OSZ 与视觉功能，增加 stable / lazer 安装目录歌曲枚举。用户要求两种来源在重建版左侧显示独立列表，实际加载并可播放；因此这次需要同时更新播放器和 DLL。

### ABI 与实现

`include/ttp_osu/library.h` 定义 ABI 1，新增序号 3 的 `ttp_osu_library_query`，不改变归档序号 1 或视觉序号 2。同步枚举接口接收来源、根目录、取消/进度回调，输出借用的 UTF-16 曲目记录；宿主在工作线程复制记录，完成后一次发布。失败不发布部分结果。

`library_stable.cpp` 只读解析 Songs 的谱面元数据、音频和背景引用，排除音效和越界引用。同集合的相同音频去重，多音频集合保留多首；停止于 HitObjects 前，避免整文件解析。`library_api.cpp` 处理 ABI、错误和回调边界。

`realm_library.cpp` 从 lazer 的 `client.realm` 读取集合、谱面元数据及逻辑文件到 SHA256 的映射。使用 Realm Core 20.1.2 的官方 Group 解析内存快照，不载入游戏程序集、不调用 RealmAccess、不迁移数据库。源文件读句柄拒绝写和删除共享，读取上限 256MiB；不兼容结构、损坏、锁定、取消均返回错误，不创建 Realm sidecar。游戏运行时发生共享冲突需先关闭游戏再试。
