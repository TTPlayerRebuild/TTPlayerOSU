# OSZ 副本导入实现与验证（2026-10-30）

## 1 本次行为

在重建版播放列表的 OSZ 音频条目上右键，根据配置路径识别出的游戏分别显示“导入到 osu!”及“导入到 osu!lazer”。普通文件、混合选择、缺失的包、不匹配的 EXE、没有可选 DLL 或没有新接口时不显示相应项。单选与多选均可，同一包里的多首音频去重为一个导入任务。

确认窗口询问是否导入，显示包名／包数和默认选中的“保留 osz 文件”。无论是否保留，都先复制一份物理 OSZ 并校验 SHA-256，原件不作为游戏参数。工作副本不是硬链接；stable 和 lazer 各用独立任务。复制、资源核验和等待提供进度及取消。

确认成功后刷新已显示的对应游戏列表。配置路径未变化也会重新扫描。本次没有增加浏览器下载后自动导入。

## 2 DLL 与宿主分工

- 新增独立 `ttp_osu_import_query`（序号 7，ABI 1），保留 1～6 号接口；结构带 size、ABI，无 STL、Realm 对象或所有权跨 DLL。
- DLL 负责游戏识别、实际存储目录、源文件锁定、流式 SHA-256、工作副本、谱面清单、明确 EXE 投递、完成核验和持久任务。
- 宿主提供通用只读压缩包成员 IStream、成员 EOF／CRC 检查、取消、进度和 UI，不增加另一套 osu! 数据库解析器。
- 播放器新增可选接口检查，旧 DLL 保留已有功能，仅不显示导入命令。
- Action 的组件下载和总包审计接受并核对 6、7 号可选导出，同时继续接受旧版 DLL；组件记录增加下载页、导入接口字段。

主要代码：`src/import.cpp`、`src/import_stable.cpp`、`src/realm_library.cpp`；宿主 `src/ui/player_window_osu_import.cpp`、`src/audio/osu_plugin_client.cpp`。

## 3 数据完整性与完成判断

读取源包时禁止其他句柄写入或删除，登记文件身份、大小、修改时间和 SHA-256。按 256 KiB 块复制，刷新后重新读取副本比较摘要。成员读取到 EOF；成员名经过相对路径验证，拒绝大小写重复或文件／目录冲突；`.osu` 进行结构解析并计算 MD5。单个谱面上限 16 MiB，成员上限 250000，总名称上限 32 Mi 字符。

stable：只读 `osu!.db`，支持 20140609 之后的已知布局，包括 20160408 条目长度、20191106 移除长度、20250107 星数浮点布局。按全部 `.osu` 相对文件名及 MD5 找到同一集合，再逐项检查文件大小和 SHA-256。数据库快照上限 256 MiB，不修改索引。

lazer：沿用配置识别及一致的只读 Realm 快照，排除删除中的集合／难度，核对集合 Files 的规范名称及哈希、有效 BeatmapInfo 的 Hash 与 MD5Hash、实际哈希存储内容。BeatmapInfo 没有持久 Path 字段，此处使用 Hash 找到文件。遵循导入器移除包内共同目录前缀的行为，不迁移数据库、不创建游戏数据库锁文件。

启动使用配置中识别出的 EXE 和正确引用的副本绝对路径，不依赖 OSZ 文件关联。stable 的 Songs 根存在同名待导入包时，副本更名加入任务标识，避免覆盖已有包。

提交后默认等待 30 秒。只有索引、所有难度和全包成员一致才返回 CONFIRMED；已有完整集合可以直接确认，不再次启动游戏。进程启动成功、副本消失、只有部分文件或难度，均不足以确认。无法确认返回 PENDING 并保留原件。

## 4 保留、任务恢复及边界

任务位于系统 Local AppData 下的 `TTPlayer/OsuImports`，实际位置遵循 Windows 配置及目录重定向。以源路径、目标和内容生成任务键；独占锁防止同任务并发。UTF-16 `task.ini` 通过临时文件、刷新和原子替换保存，记录源路径、EXE、工作文件、摘要和状态。重复选择 pending 任务继续核验，不重复启动游戏。取消已提交任务仅停止等待；不关闭游戏，不删除可能仍在读取的副本。

**播放列表引用保护是当前实际行为：** 当前入口来自 OSZ 歌曲条目，宿主始终传入 SOURCE_REFERENCED。因此取消保留后，成功提示会说明原包仍被列表使用并保留它。没有实现源包到游戏曲库的引用迁移，不会为了执行清理而使音频／背景失效。

独立 DLL 接口允许未来无引用的宿主在取消保留时请求 Shell 回收：再次核对源文件身份与内容，用已验证句柄重命名隔离后请求回收，失败尝试还原原名，不覆盖后来创建的同名文件。恢复临时路径持久写入任务记录；回收结果与导入结果分开。具体回收行为仍受 Windows Shell 与回收站策略约束，当前播放列表入口不执行这一清理分支。

剩余边界：

- 源包已位于游戏实际扫描／存储目录中时，本版拒绝提交，避免游戏自发扫描原件破坏保留承诺；尚未实现为这种来源另选归档位置的 UI。
- 游戏一直未更新索引、数据库被占用、结构不兼容、难度被拒绝时可能保持 PENDING。重复操作是继续核验，尚无“强制重新提交”入口或任务管理窗口。
- 工作副本使用 Local AppData，未实现优先在 Songs 同卷创建临时目录；跨卷真实游戏导入尚待测试。
- 当前验证完整包字节与曲库记录，不证明游戏可以游玩每个难度；损坏／缺少音频的谱面包不应据此视为可玩性测试通过。
- 待处理任务不自动清理，不自动迁移或修改原包及游戏数据库。大包需要额外磁盘空间和校验时间。
