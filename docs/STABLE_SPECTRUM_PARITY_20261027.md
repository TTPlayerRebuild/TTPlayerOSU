# osu! stable 环形频谱对照与修复（2026-10-27）

## 1. 结论

截图中的主要差异来自重建版的程序生成纹理：将原版的“长空心线＋短实心条”画成了两个几乎等长的条纹，左侧开口、圆头、线宽、透明度也不同。与千千静听图案的橙色外环无关。

本次在 `ttp_osu.dll` 内恢复原频谱资源、高清尺寸规则和更新边界。中心PNG不变，不增加白色外环；频谱配色仍使用宿主设置，lazer频谱保持独立。公共ABI、宿主EXE和Action无需调整。

## 3. 修正内容

### 3.1 原频谱纹理

删除128×32近似生成图，嵌入原资源提取产物：

| 分支 | 文件 | 尺寸 | RCDATA |
| --- | --- | --- | ---: |
| 普通 | `assets/osu-menu-spectrum.png` | 115×38 | 116 |
| 高清 | `assets/osu-menu-spectrum@2x.png` | 230×75 | 115 |

高清图的长空心线左边开口、右边圆头；下部实心条只有100/230长度。旧实现将下部实心条几乎画成全长，并使用0.7透明度，形成截图中的长亮线。现在保留原透明通道、比例和间距。

现有GDI+解码为预乘BGRA，CPU和D3D9使用同一份像素。源PNG不改写，来源和摘要见 [assets/README.md](../assets/README.md)。

### 3.2 高清高度与裁剪

原程序将@2x高度75整数除以2得到37；绘制源矩形再乘2，只画前74行。不能直接按37.5或38绘制。

- 有效画布高度 `<800`：115×38资源、完整UV，图元逻辑高度 `38×0.5×480/768 = 11.875`。
- 有效画布高度 `≥800`：230×75资源、UV下界 `74/75`，图元逻辑高度 `37×0.5×480/768 = 11.5625`。

有效高度为 `min(H,floor(W×0.8))`，竖屏按受限画布选择。长度仍为 `115×480/768×bar`；根半径、前景视差、左边中点原点保持原算法。

原游戏还有强制高/低分辨率配置和GPU最大纹理尺寸大于2048的条件。插件没有映射这些游戏配置，谱图本身最大只有230×75；保留现有设备上传适配，没有把整个游戏资源族的2048限制施加给小纹理。

### 3.3 10ms边界与拖尾

旧实现恰好10ms就推进offset。原版只在时间溢出时推进；恰好10ms保留累积值，下一帧先在旧offset以0ms更新一次幅度，再推进50个FFT位置。

这次0ms更新会把新音频幅度注入旧角度，形成拖尾。已恢复原控制流，避免边界换音频数据时漏掉该方向。

没有有效音频时，FFT应先按整帧时间衰减一次，再分片推进条纹。旧实现每个分片衰减FFT，会在暂停长帧的前几个角度注入过强的旧幅度。原FFT阈值在乘法前判断，bar阈值在乘法后判断，两者分别保留。

### 3.4 数值细节与已一致部分

- bar衰减以double乘法完成后转float。
- 角度使用原float表达式 `6.2831855f×(0.4f+i/1024f×4f)`。
- 仅stable频谱按原Sprite规则截断alpha至byte，其他效果的取整不变。
- 1024条频谱绕四圈、重叠在256个方向、倒序下标、加法混合原本正确，继续保留。
